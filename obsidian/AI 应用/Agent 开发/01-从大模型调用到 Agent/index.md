# 从大模型调用到 Agent

这一部分想解决的问题很简单：我们明明已经能用一条 API 调用上大模型，为什么还会继续发展出 Agent 这种更复杂的系统？

如果只把大模型当成“会回答问题的接口”，很容易觉得 Agent 只是换了个名字。但当任务开始涉及读取文件、调用工具、访问最新信息、分步骤执行和持续纠错时，单次模型调用就不够了，Agent 也就自然出现了。

## 本部分主线

你可以先把这一部分理解成一条逐层加能力的链路：

1. 大模型：负责理解、推理和生成。
2. Chat：把输入组织成消息，让模型在上下文里回复。
3. Tool Calling：让模型可以表达“我需要调用某个工具”。
4. Agent Loop：让程序接住工具调用结果，再把结果喂回模型继续思考。
5. Agent：把模型、工具、记忆、权限和工作流组合成一个可执行系统。
