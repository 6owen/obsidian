# 从一条 curl 请求开始

> [!note]
> 这一篇不急着讲 Agent，也不急着讲框架。先把一条最小请求拆开看清楚：当我们说“调用大模型”时，到底在发送什么、控制什么、收到什么。

## 1. 这一篇要拆什么

![[assets/01-02-curl-request-illustrations/01-request-machine.excalidraw]]

很多人第一次看到大模型 API，会觉得它非常神秘。但如果你把外层包装拿掉，它其实就是一条普通的 HTTP 请求：

- 你把一段上下文发过去。
- 服务端调用某个模型处理。
- 再把结果返回给你。

难点不在“怎么发请求”，而在“你到底喂了什么”和“这些字段分别会影响什么”。

## 2. 一条最小请求长什么样

先看一个最小可用版本：

\`\`\`bash
curl https://xxx.com/v1/chat/completions \\
  -H "Authorization: Bearer $NEW_API_KEY" \\
  -H "Content-Type: application/json" \\
  -d '{
    "model": "DeepSeek-V4-Flash-0731",
    "messages": [
      {
        "role": "user",
        "content": "Explain quantum entanglement in one paragraph."
      }
    ],
    "temperature": 0.7
  }'
\`\`\`

如果用 JavaScript 写，本质也一样：

\`\`\`js
const response = await fetch("https://xxx.com/v1/chat/completions", {
  method: "POST",
  headers: {
    Authorization: \`Bearer \${process.env.NEW_API_KEY}\`,
    "Content-Type": "application/json",
  },
  body: JSON.stringify({
    model: "DeepSeek-V4-Flash-0731",
    messages: [
      {
        role: "user",
        content: "Explain quantum entanglement in one paragraph.",
      },
    ],
    temperature: 0.7,
  }),
})

const data = await response.json()
console.log(data)
\`\`\`

这条请求里最值得先认识的是下面这些字段：

| 字段 | 作用 | 你可以先把它理解成 |
| --- | --- | --- |
| endpoint | 请求地址 | 你在敲哪扇门 |
| API Key | 鉴权 | 你有没有权限进门 |
| model | 指定模型 | 你在叫谁干活 |
| messages | 输入上下文 | 你到底给它看了什么 |
| temperature | 生成风格 | 它回答得更稳还是更发散 |

## 3. Endpoint：你在敲哪扇门

\`https://xxx.com/v1/chat/completions\` 这一段就是接口地址，也就是 endpoint。

它至少告诉你三件事：

- 你在访问哪家服务。
- 你在访问哪个 API 版本。
- 你在调用哪类能力。

例如：

- \`/v1/\`：说明是某个版本的 API。
- \`/chat/completions\`：说明这是一个对话补全接口。

换句话说，endpoint 决定的是“你把请求送到哪里”，不是“模型会怎么想”。

## 4. API Key：你有没有权限进门

\`Authorization: Bearer $NEW_API_KEY\` 这一行是鉴权信息。

你可以把它理解成：

- 这是你访问模型服务的身份凭证。
- 服务端据此判断你有没有权限调用。
- 费用统计、额度控制、风控限制，通常也和它有关。

实践里要记住两点：

- 不要把 Key 写死在前端代码里。
- 优先放到环境变量或服务端配置里。

## 5. Model：你在叫谁干活

\`"model": "DeepSeek-V4-Flash-0731"\` 这一段是在告诉服务端：这次到底要用哪个模型来处理。

模型名背后通常隐含这些差异：

- 速度
- 价格
- 上下文长度
- 推理能力
- 工具调用能力

所以“换模型”并不只是换一个名字，而是在换一组能力和成本结构。

## 6. Messages：真正决定结果的输入

如果说模型是大脑，那 \`messages\` 就是这次思考前真正塞进它脑子里的内容。

最简单的时候，里面可能只有一句用户提问：

\`\`\`json
[
  {
    "role": "user",
    "content": "Explain quantum entanglement in one paragraph."
  }
]
\`\`\`

但真实应用里，它通常会越来越复杂：

- system：系统要求
- user：用户最新问题
- assistant：模型前面的回复
- tool：工具执行结果
- 额外拼进去的检索资料、技能说明、上下文摘要

## 7. Temperature、max_tokens、stream 在控制什么

除了核心输入，调用模型时往往还会带一些控制参数。

### temperature

它主要控制输出的发散程度。

- 更低：更稳、更保守。
- 更高：更发散、更有变化。

### max_tokens

它大致控制“这次最多让模型说多长”。

### stream

它决定你是等整段内容一次性回来，还是边生成边看到结果。

> stream 改变的是交互体验，不是模型本身的智能水平。

## 8. 为什么这还不是 Agent

看完这些字段以后，你会发现一个关键事实：

> 这条请求已经足够构成一次 AI 调用，但它还不足以构成一个 Agent。

因为它本质上还是：

- 你给一次输入
- 模型给一次输出
- 整个过程到这里就结束

它没有天然具备：

- 工具调用
- 多步循环
- 状态管理
- 停止条件

## 9. 这篇先记住什么

1. 调用大模型，本质上就是向某个 endpoint 发送一条带上下文的请求。
2. \`model\` 决定这次谁来回答，\`messages\` 决定它看到了什么。
3. \`temperature\`、\`max_tokens\`、\`stream\` 这类参数控制的是输出风格、长度和交互方式。
4. 一条 \`curl\` 请求已经是完整的 AI 调用，但还不是 Agent。
