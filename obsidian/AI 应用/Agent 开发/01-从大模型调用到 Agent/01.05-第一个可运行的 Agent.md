# 第一个可运行的 Agent

> [!note]
> 这一篇不追求“强大”，只追求“真的跑起来”。目标是做出一个最小 Agent：有模型、有指令、有一个工具、有循环、有结束条件。

## 1. 这一篇的目标

![[assets/01-05-first-agent-illustrations/01-agent-workbench.excalidraw]]

到了这里，我们已经有了四块积木：

- 模型调用
- Chat messages
- Tool Calling
- Agent Loop

现在要做的，就是把它们拼成一个最小可运行系统。

## 2. 先选一个窄任务

一个好的第一个 Agent，最好符合这几个条件：

- 目标清楚
- 工具很少
- 成功标准明确
- 失败了也容易定位原因

这里给一个很适合练手的例子：

> 给定一篇 Markdown 笔记路径，如果回答需要原文内容，就调用 \`read_note\` 工具读取笔记，再生成摘要或答案。

这个任务的好处是：

- 只有一个工具
- 目标明确
- 结果可验证
- 很接近真实知识助手的雏形

## 3. 先定义系统指令

系统指令不是越长越好，而是越清楚越好。

最小版本可以这样写：

\`\`\`text
你是一个笔记助手。
当用户的问题需要依赖某篇笔记的原文时，优先调用 read_note 工具读取内容。
如果信息已经足够，就直接回答。
不要假装读过你没有读取的笔记。
当证据不足时，明确说明。
\`\`\`

## 4. 定义唯一一个工具

先从一个工具开始就够了。

\`\`\`json
{
  "type": "function",
  "function": {
    "name": "read_note",
    "description": "Read a markdown note by relative path and return its content.",
    "parameters": {
      "type": "object",
      "properties": {
        "path": {
          "type": "string",
          "description": "Relative path of the markdown note."
        }
      },
      "required": ["path"]
    }
  }
}
\`\`\`

## 5. 把 loop 串起来

下面是一个最小可运行骨架。它不是生产代码，但足够把核心原理跑通。

\`\`\`js
async function runAgent(userInput) {
  const messages = [
    {
      role: "system",
      content:
        "你是一个笔记助手。当用户的问题需要依赖某篇笔记的原文时，优先调用 read_note 工具读取内容。如果信息已经足够，就直接回答。不要假装读过你没有读取的笔记。",
    },
    {
      role: "user",
      content: userInput,
    },
  ]

  for (let step = 0; step < 6; step++) {
    const data = await callModel(messages)
    const message = data.choices[0].message

    messages.push(message)

    if (!message.tool_calls || message.tool_calls.length === 0) {
      return message.content
    }

    for (const toolCall of message.tool_calls) {
      const result = await executeTool(toolCall)

      messages.push({
        role: "tool",
        tool_call_id: toolCall.id,
        content: JSON.stringify(result),
      })
    }
  }

  throw new Error("Agent stopped: step limit reached")
}
\`\`\`

这段代码最小但完整，已经具备：

- 模型调用
- 一个工具
- 工具执行
- 结果回传
- 多轮循环
- 步数限制

## 6. 跑起来以后，先看什么

第一次跑通以后，不要急着追求“智能”，先看可观测性。

至少应该记录这些信息：

- 第几步
- 模型有没有调用工具
- 调了哪个工具
- 参数是什么
- 工具执行结果是什么
- 最终为什么停下

最简单的办法，就是先打日志。

## 7. 第一次失败很正常

第一个 Agent 最容易出现这些问题：

- 工具参数漂移
- 工具结果太长
- 太早结束
- 没有权限边界

第一个 Agent 的目标不是“百分之百正确”，而是：

> 你终于拥有了一个可以调、可以看、可以改进的最小执行系统。

## 8. 这篇先记住什么

1. 第一个 Agent 最好从单工具、窄任务开始。
2. 一个最小 Agent 至少要有模型、指令、工具、loop 和停止条件。
3. 真正让系统可迭代的，不只是能跑，而是能看见它怎么跑。
4. 从这里往后，Agent 的难点就不再只是模型，而是知识、工具、记忆和工作流的组合。
