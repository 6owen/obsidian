# Part 01 配图方案与 imagegen prompts

> [!note]
> 这份文件按小黑正文配图工作流整理 Part 01 的配图策略，并为后续真正调用 imagegen 预留可直接复用的 prompt。当前会话里没有暴露可直接调用的 built-in image_gen 入口，所以这里先保存最终方案，并用本地插图占位。

## 01.01 从一次 Chat 调用到为什么需要 Agent

- 放置位置：标题下，导语 note 前，作为首图
- 主题：同一个模型，从单次 Chat 长出 Agent 外壳
- 核心意思：Agent 不是换了一个更神秘的模型，而是在同一个模型外面加上工具、状态和循环，让系统可以继续做事
- 结构类型：前后对比
- 小黑在图里做什么：左边喂一张写着 curl 的小纸条；右边推着装满 history、tools、state、MCP 的手推车往同一个模型里塞，并把结果继续回传
- 建议中文标注词：curl / 回答 / history / tools / state / 结果回传
- 当前占位图：![[assets/01-01-from-chat-to-agent-illustrations/00-hero-from-chat-to-agent.svg]]

## 01.02 从一条 curl 请求开始

- 放置位置：正文第 1 节后
- 主题：一条请求被拆包成几个关键字段
- 核心意思：所谓调用大模型，本质上就是把 request 包拆开，看清 endpoint、key、model、messages、temperature 分别在干什么
- 结构类型：概念隐喻
- 小黑在图里做什么：小黑站在一台低科技拆包机旁，把一个写着 request 的纸箱塞进机器里，右边吐出 response
- 建议中文标注词：请求 / 模型 / 返回 / messages / temperature
- 当前占位图：![[assets/01-02-curl-request-illustrations/01-request-machine.svg]]

## 01.03 从模型调用到工具调用

- 放置位置：正文第 1 节后
- 主题：模型发出工具调用意图，但真正执行的是程序
- 核心意思：Tool Calling 是意图协议，不是模型自己去执行动作
- 结构类型：系统局部
- 小黑在图里做什么：小黑在中间像接线员一样接住模型吐出来的调用单，再把它接到右侧不同工具上
- 建议中文标注词：意图 / 校验 / 工具 / 结果
- 当前占位图：![[assets/01-03-tool-calling-illustrations/01-tool-switchboard.svg]]

## 01.04 Agent Loop

- 放置位置：正文第 1 节后
- 主题：工具结果回来以后，系统要继续循环
- 核心意思：Agent Loop 不是新模型，而是观察、决策、执行、回传的可反复闭环
- 结构类型：地图路线
- 小黑在图里做什么：小黑抱着结果纸条，在一个圆形轨道上不断把结果送回模型中间的洞口
- 建议中文标注词：观察 / 决策 / 执行 / 回传 / 停止
- 当前占位图：![[assets/01-04-agent-loop-illustrations/01-loop-wheel.svg]]

## 01.05 第一个可运行的 Agent

- 放置位置：正文第 1 节后
- 主题：把模型、工具、循环组装成一个最小工作台
- 核心意思：第一个 Agent 不需要全能，只要把一个窄任务真正跑通
- 结构类型：方法分层
- 小黑在图里做什么：小黑在一张怪工作台前，往一个小机器里塞三块积木：system、tool、loop，右边吐出一张完成的笔记
- 建议中文标注词：system / tool / loop / 任务 / 输出
- 当前占位图：![[assets/01-05-first-agent-illustrations/01-agent-workbench.svg]]

## 后续真的用 imagegen 时的执行建议

- 每篇先只生成 1 张正文主图，不要平均铺太多图
- 先替换 01.02～01.05 的占位 SVG，再视效果补第二张
- 生成后重点检查：小黑是不是动作主体、画面是不是太像 PPT、左上角有没有出现标题、中文批注是不是太多
