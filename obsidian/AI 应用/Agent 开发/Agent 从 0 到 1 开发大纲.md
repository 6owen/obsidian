# Agent 从 0 到 1 开发大纲

> [!note] 写作目标
> 记录一个 Agent 从想法、最小实现到可评测产品的完整开发过程。重点写清楚：为什么这样设计、遇到了什么问题、如何验证，以及下一次会如何改进。

## 1. 为什么要做这个 Agent

- 想解决什么问题？
- 目标用户是谁？
- 为什么普通脚本或单次模型调用不够？
- 希望通过这个项目学会什么？

## 2. 定义第一版目标与边界

- 输入是什么？
- 输出是什么？
- Agent 可以使用哪些工具？
- 什么结果算完成？
- 第一版明确不做什么？

## 3. Agent 的最小工作原理

- 模型、提示词、消息和工具分别承担什么职责？
- Agent 循环如何运行？
- Agent 与普通聊天机器人的区别是什么？

## 4. 技术选型与项目初始化

- 为什么选择当前语言和技术栈？
- 是否使用 Agent 框架？为什么？
- 项目目录如何划分？
- 环境变量、依赖和启动命令如何管理？

## 5. 实现第一个可运行版本

- 接入模型
- 编写系统提示词
- 接收用户任务
- 获得并展示模型回答
- 保存一次完整运行记录

## 6. 加入工具调用

- 第一个工具解决什么问题？
- 如何描述和注册工具？
- 如何校验工具参数？
- 如何把工具结果交还给模型？
- 如何处理调用失败和重复调用？

## 7. 实现 Agent 循环

- 什么时候继续执行？
- 什么时候结束？
- 如何限制最大步骤、时间和费用？
- 如何避免死循环？

## 8. 上下文、状态与记忆

- 哪些信息只属于当前任务？
- 哪些信息需要跨任务保留？
- 上下文过长时如何处理？
- 第一版是否真的需要长期记忆或 RAG？

## 9. 可观测性与调试

- 每一步需要记录哪些数据？
- 如何查看模型输入、工具参数和工具结果？
- 如何定位一次失败是 Prompt、模型、工具还是业务逻辑导致的？
- 如何保护密钥与私人数据？

## 10. 评测与验收

- 建立测试任务集
- 定义成功、部分成功和失败
- 检查结果正确性、稳定性、速度与成本
- 保存典型成功案例和失败案例
- 修改后如何做回归测试？

## 11. 从 Demo 到可用产品

- 用户如何使用它？
- 是否需要 Web 界面、CLI 或 API？
- 如何处理并发、权限和异常？
- 如何部署、监控和回滚？

## 12. 关键问题与失败案例

- 最难定位的问题是什么？
- 哪些设计一开始想复杂了？
- 哪些地方不能只依赖模型？
- 哪次失败改变了后续架构？

## 13. 阶段复盘

- 最终实现了什么？
- 哪些目标没有完成？
- 最重要的三条经验是什么？
- 如果重新开发一次，会调整什么顺序？
- 下一阶段准备增加什么能力？

## 附录

### 开发日志

按日期记录当天的目标、修改、验证结果和遗留问题。

### 技术决策

记录重要选择、备选方案、选择依据和实际结果。

### 术语与参考资料

整理开发过程中反复出现的概念和资料来源。
