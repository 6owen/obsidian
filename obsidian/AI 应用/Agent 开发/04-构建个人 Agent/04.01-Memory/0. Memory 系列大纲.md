# Memory 系列大纲：给天生无记忆的 Agent 造一个记忆

> [!note]
> 这是一个用叙事方法讲透 Agent Memory 的写作系列。叙事方法论来自 [[0. 写作学习总纲：从故事结构开始学习叙事]]（故事 = 欲望 + 障碍 + 选择 + 代价 + 改变），技术底稿来自本目录的调研文章。目标不是写得像小说，而是**把枯燥的原理放进故事里讲**：70% 技术，30% 故事。

## 1. 系列定位

- **核心主题**：Agent Memory——它是什么、为什么需要、市面怎么实现、怎么构建自己的
- **系列架构**：**（是什么 + 为什么）→ 怎么做**。第一篇一篇讲透并闭环（可独立成书），第二幕开放生长（5～10 篇不等，由真实经历决定）
- **读者成长阶梯**：篇 1 一篇同时服务"想搞懂的人"（旁观者 + 使用者）和工程师，施工连载记录"我"从学习者变成施工者的过程
- **写作原则**：每篇解决一个问题、打开一个问题（钩子链）；每篇内部 State A ≠ State B（推进检查）

## 3. 第一幕 · 是什么 + 为什么（1 篇）

### 篇 1：《Agent = 模型 + harness，记忆是插件》

> 备选标题：《Agent 的记忆是外挂的：从无状态模型到市面实现》《Agent Memory 全景：结构、动机与四家实现》

**骨架（四点，按此展开）**：

```text
1. Agent = 模型 + harness
2. harness 有很多功能插件，memory 是其中之一
3. 为什么需要 memory：因为要记住事情（两个出厂设定决定的）
4. 市面 memory 的实现方式展开：四家形态 → 差异本质是五道选择题
```

| 要素 | 内容 |
| --- | --- |
| 主题句（认知改变） | Agent = 模型 + harness；模型天生无状态，记忆是 harness 的一个**功能插件**——所以每家的记忆长得完全不一样：差异不是功能多寡，是设计哲学的差异；构建自己的 memory 不是选产品，是做五道选择题 |
| 被推翻的旧认知 | "记忆是模型/Agent 自带的能力"、"memory 就是聊天记录存个数据库"；"窗口变大了就不需要记忆了" → context rot 还在；"选一个功能最全的就行" |
| 欲望 | 让 Agent 记住事情：跨会话连续、长对话不失焦；进而想直接抄一个最好的实现 |
| 障碍 | 出厂设定，不是故障：**无状态**（跨会话归零）+ **有限窗口**（context rot，塞满挤掉开头）；四家（OpenClaw / Mastra / Claude Code / pi）互不兼容、各有取舍，没有"最全" |
| 选择 | 先看清结构（模型 + harness + 插件位），再横向展开市面实现，把差异提炼成五道所有实现都必须回答的选择题 |
| 代价 | 记忆不是免费的：注入花预算、检索加延迟、维护花纪律；且每道选择题都要放弃点什么：文件慢、数据库锁、pi 白纸什么都要自己盖 |
| 引子场景 | 跨会话开场：昨天花一下午定下的技术方案，今天新开会话，它礼貌地问"你好，请问我们今天做什么？" |
| 信息控制 | 先场景后结构；第 4 节**先形态后取舍**——上半场只描述形态与行为，下半场才进入 vs、优劣、选择题 |
| 对比组织方式 | 下半场**按选择题组织，不按产品巡礼**——每道题下面才是四家的答案 |
| 结尾钩子 | 五道题我的答卷写完了（通用 Memory 设计），但纸面设计 ≠ 跑起来的系统——开始施工 → 篇 2+ |

**第 2 节素材**（harness 插件谱系）：循环、工具、权限、上下文文件、记忆、可观测……列一张能力清单表，memory 定位其一。**pi 是最好的例证**：4 个内置工具 + 极小核心，一切皆扩展——pi 出厂根本没有 memory，要用就自己装，恰好证明"记忆是 harness 插件，不是模型能力"（[[04.01-pi 与 Mastra 怎么选]]）。

**第 4 节展开方式（原"概览"与"选择题"两篇的合并点）**：

| 阶段 | 内容 | 约束 |
| --- | --- | --- |
| 上半 · 四家形态 | 每家一小节："记忆长什么样 + 用起来什么行为"，只描述不评价 | 每家约 1/4 节，机制细节点到为止 |
| 下半 · 五道选择题 | 差异深挖：谁来写、什么时候遗忘、怎么被想起、信不信它……每道题下面才是四家的答案 | 本篇技术重心，按题组织不按产品巡礼 |

四家概览素材（上半场）：

| 家 | 一句话形态 | 小节引子 |
| --- | --- | --- |
| Mastra | 数据库派：四件套（message history / working memory / semantic recall / observational memory） | 亲历开场：配置完用得很顺，直到想问"这记忆是谁、什么时候写的" |
| OpenClaw | 文件派：md 是本体，SQLite 只是索引，夜里做梦做减法 | workspace 里打开 MEMORY.md 和 memory/ 目录 |
| Claude Code | 管家派：CLAUDE.md 指令文件 + auto memory 目录（⚠️ 写前对照官方文档核验） | 一个会话里它默默建了 memory 文件 |
| pi | 白纸派：没有内置记忆，扩展自己装 | 装完 pi 找 memory 配置，发现没有 |

五道选择题（下半场骨架）：

| 选择题 | 分歧点 |
| --- | --- |
| 真相放在哪 | 文件（OpenClaw / Claude Code）vs 数据库（Mastra）vs 没有（pi） |
| 谁来写 | 主模型调工具 vs 后台小模型 vs 框架自动 |
| 什么时候遗忘 | token 阈值（Mastra OM）vs 定时做梦（OpenClaw）vs 压缩时（Claude Code） |
| 怎么被想起 | 注入 / 搜索 / 触发短语 / 深召回梯队 |
| 信不信它 | provenance 分离 + 污点门 vs 基本不设防 |

## 4. 第二幕 · 怎么做（N 篇，开放）

**文体是施工日志（build log），不是设计文**：

- 每篇 = 一次迭代 = 一个完整故事（真实场景 → 出问题 → 尝试 → 意外 → 改变）
- 不求尽善尽美：在别人的基础上做一个——**继承设计而不是继承代码**，基座是格式（Markdown + 挂载点约定），OpenClaw/Mastra 的机制是随时可借的零件库
- 钩子自动成立：下一篇 = 下一个暴露的缺陷
- 可随时收尾：没有新问题 = 本阶段写完

**候选篇目（按预期暴露顺序，写时再调整）**：

| # | 暂定题目 | 预期暴露的问题 |
| --- | --- | --- |
| 2 | 基座盘点：这个 vault 就是我的 memory v0.1 | 现状已是一个实例（obsidian 真相层 + wiki 蒸馏层 + AGENTS.md 挂载），缺 journal 隔离、召回、隐私分级 |
| 3 | 第一次"做梦"：手动蒸馏时我在模仿 OpenClaw 的门槛 | 蒸馏无门槛会烂掉 |
| 4 | 让记忆被想起：没有索引时的召回灾难 | 记了但想不起来 = 没记 |
| 5 | import：从 Mastra 项目里抢救记忆 | 只复制、按来源隔离、不合并 |
| 6 | journal 隔离：多个 Agent 写同一个目录之后 | 共写冲突 |
| 7 | 隐私分级：要 export 给别的工具时才慌 | sensitive 内容不能随便出去 |
| 8+ | （开放）lint / 记忆健康度 / …… | 由真实使用决定 |

## 5. 每篇统一内部模板

```text
1. 场景引子（300–500 字）：真实故障或发现，只抛问题不给答案
2. 原理展开（主体）：本篇核心机制，选一个"主角系统"讲透
3. 多家对照（表格 + 分析）：同一问题的不同答案（篇 1 第 4 节上半的四家形态概览就是这个形态）
4. 认知改变收尾 + 打开下一篇的钩子
```

配套纪律：

- **70% 技术 + 30% 故事**，语言朴素，不为小说感堆辞藻
- 因果词显式用：因为 / 所以 / 但是 / 因此 / 不得不——通读时把"然后"换掉
- 每个抽象判断跟一个具体细节（30k 阈值、凌晨 3 点 cron、5–40 倍压缩、最多丢 25% 旧条目……）
- 系统当**配角人物**写：Mastra 工程派（后台小模型军团）、OpenClaw 极简派（一支笔一叠 md）、pi 白纸派（出厂无记忆）、Claude Code 管家派（规矩多）

## 6. 系列级检查表（每篇写完过一遍）

| 检查项 | 问题 |
| --- | --- |
| 推进 | 这篇开始和结束，什么变了？（State A ≠ State B） |
| 钩子链 | 上一篇结尾的问题，是不是这篇的开场？ |
| 人物弧 | 主人公在篇 1 是学习者，第二幕起是施工者——身份转变是否成立？ |
| 细节 | 有没有具体数字、时间、动作、对话？ |
| 信息控制 | 哪个答案可以晚一点揭晓？是否做到了先见问题后见原理？ |
| 第 4 节节奏 | 先形态概览、再按选择题深挖；没有变成产品巡礼，取舍没有提前到形态阶段 |
