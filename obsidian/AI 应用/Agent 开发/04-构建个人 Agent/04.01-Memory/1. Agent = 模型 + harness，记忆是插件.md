# Agent = 模型 + harness，记忆是插件

> [!note]
> 这一篇不讲任何框架的用法。目标只有一个：把 Agent 拆成"模型 + harness"两层，看清记忆是 harness 的一个功能插件——所以每家的记忆长得完全不一样，差异不是功能多寡，是设计哲学。

## 开头大纲

1. **场景引子**（300–500 字）：昨天花一下午定下的技术方案，今天新开会话，它礼貌地问"你好，请问我们今天做什么？"——只抛问题，不给答案
2. **Agent = 模型 + harness**：先把 Agent 拆开，模型是模型，harness 是 harness
3. **harness 有很多功能插件，memory 是其中之一**：列一张能力清单（循环、工具、权限、上下文文件、记忆、可观测……），memory 定位其一；pi 作例证——出厂根本没有 memory，要用就自己装
4. **为什么需要 memory：因为要记住事情**：两个出厂设定决定的——无状态（跨会话归零）+ 有限窗口（context rot，塞满挤掉开头）
5. **市面 memory 的实现方式展开**：
   - 上半场 · 四家形态概览：Mastra 数据库派 / OpenClaw 文件派 / Claude Code 管家派 / pi 白纸派——只描述形态与行为，不评价
   - 下半场 · 五道选择题：真相放在哪 / 谁来写 / 什么时候遗忘 / 怎么被想起 / 信不信它——按题组织，不按产品巡礼
6. **收尾**：认知改变重申（记忆是插件，不是模型能力）+ 我的答卷 + "纸面设计 ≠ 跑起来的系统"——钩子进第二幕施工日志
