# 没有记忆的模型，怎么做出有记忆的 Agent

> [!note]
> 这一篇不讲框架用法。目标只有一个：把 Agent 拆成"模型 + harness"两层，看清记忆不在模型里，在 harness 里——所以每家做的记忆长得完全不一样。

## 开头大纲

1. **场景引子**（300–500 字）：昨天花一下午定下的技术方案，今天新开会话，它礼貌地问"你好，请问我们今天做什么？"——只抛问题，不给答案
2. **Agent = 模型 + harness**：模型是无状态的大脑，只负责想，本身记不住任何事；harness 给它装上四肢和器官——循环、工具、权限、上下文、可观测，全是 harness 的功能。往 harness 里加一个 memory，就是给模型加上记忆
3. **介绍一下 memory**：为什么需要——模型的两个出厂设定：无状态（跨会话归零）+ 有限窗口（context rot，塞满挤掉开头）；顺带澄清一个常见误会：**prompt 缓存不是记忆**——它复用的是相同前缀的算力结果（省钱、提速、几分钟过期），缓存记的是计算，不是内容，换个说法提问就 miss；所以"记住事情"必须由 harness 代劳：跨会话连续、长对话不失焦。反向伏笔：记忆的注入位置会影响缓存命中率（前缀要稳、检索内容放后面），第二幕施工会遇到
4. **市面上的 memory 怎么做**：OpenClaw、Claude Code、pi，加上我亲历的 Mastra——每家一小节，讲记忆长什么样、用起来是什么行为
5. **异同**：把差异提炼成几道所有实现都要回答的选择题——真相放在哪 / 谁来写 / 什么时候遗忘 / 怎么被想起 / 信不信它
6. **收尾**：认知改变重申（记忆是 harness 给的，不是模型自带的）+ 我的答卷 + "纸面设计 ≠ 跑起来的系统"——钩子进第二幕施工日志
