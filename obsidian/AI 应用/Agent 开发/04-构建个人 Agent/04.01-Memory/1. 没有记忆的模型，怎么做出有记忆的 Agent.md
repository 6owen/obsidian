# 没有记忆的模型，怎么做出有记忆的 Agent

## 一、为什么需要 Memory

**目标：讲清 Agent 为什么需要记忆，以及记忆怎样发挥作用。**

- Agent ≈ 模型 + harness：Memory 在其中负责什么。
- 模型调用不会自动继承过去的经历；跨会话如何延续偏好、决定和任务背景。
- 上下文有限，不能一直堆积历史；聊天记录、当前上下文与长期记忆有什么区别。
- 记忆的基本闭环：保存信息 → 按需找回 → 放入上下文 → 影响回答与行动。

## 二、通过对比现有实现，理解 Memory 的设计

**目标：看懂不同系统怎么做、为什么这样做，从中找到自己可以借鉴的方法。**

主要案例：**OpenClaw、Claude Code、pi Agent、Mastra**。补充少量其他开源 Memory 方案，避免只看到 Agent 内置记忆这一种形态。

统一沿以下问题介绍和比较：

| 问题 | 要了解什么 |
| --- | --- |
| 记什么、存在哪？ | 原始记录、提炼后的记忆，以及文件、数据库和索引的分工 |
| 谁来写、什么时候写？ | 人工、主 Agent、应用程序或后台处理如何参与 |
| 怎么想起来？ | 固定加载、按需读取、检索，以及怎样进入上下文 |
| 怎么维护？ | 总结、更新、纠错与遗忘 |
| 有什么取舍？ | 使用效果、成本、可控性和迁移难度 |

**对比后的落点：**提炼共同机制与可借鉴的设计，说明自己为什么倾向 OpenClaw 式的文件记忆——文件作为本体，SQLite 等作为可重建索引。具体目标和方法留给第二篇。
