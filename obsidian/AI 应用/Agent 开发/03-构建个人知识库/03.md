# 构建个人知识库

这一部分想解决的问题是：当我们已经有了模型、工具和检索能力之后，怎样才能让 Codex、Claude Code 这类 Agent 真正理解并使用“我自己的资料”。

很多人已经有了大量笔记、代码、网页收藏、项目文档，但这些内容往往只是“堆在那里”。对人来说，它们可能还能靠记忆和搜索勉强找到；对 Agent 来说，如果没有边界、结构、来源和入口，就很难稳定使用。

所以 Part 03 的重点，不是“再造一个炫酷数据库”，而是把个人资料整理成一个可读取、可追溯、可增量更新、可被 Agent 按需使用的个人知识系统。

## 本部分主线

Part 02 主要解决的是：模型为什么需要外部知识、检索链路怎么工作、RAG 为什么常常在生产环境翻车。

Part 03 则继续往前一步，回答另一个更贴近个人使用的问题：

> 如果我的资料主要在 Obsidian、本地文件、代码仓库和一些长期积累的文档里，我应该怎么组织它们，才能让 Agent 稳定使用？

这件事的难点不在“有没有向量库”，而在于几个更基础的问题：

- 原始资料和 AI 整理后的内容要不要分开
- 哪些内容应该保留原文，哪些内容可以总结成 Wiki
- 结论怎么追溯到原始来源
- 当笔记持续新增时，系统怎么增量更新
- 当 Agent 回答时，它应该先看什么，后看什么

## 这一部分最想讲清什么

| 问题 | 结论方向 |
| --- | --- |
| 我已经有很多笔记了，为什么还不够？ | 因为“可写”不等于“可检索、可追溯、可被 Agent 使用”。 |
| 个人知识库是不是就是向量数据库？ | 不是。向量检索只是其中一层能力，不是全部。 |
| 为什么要分 Raw、Index、Wiki、Memory？ | 因为原始资料、检索索引、派生知识和持续状态解决的是不同问题。 |
| 知识库和记忆是一回事吗？ | 不是。知识库偏向资料与结构，记忆偏向偏好、状态与历史选择。 |
| 对 Agent 来说最重要的是什么？ | 不是“知道很多”，而是“知道先去哪看、能不能回到原文、回答时是否带证据”。 |
