# 知识分层

![[assets/03-02-layered-kb-illustrations/01-layered-kb-hero.svg]]

> [!note]
> 当你真的开始搭个人知识系统时，最容易出问题的地方往往不是模型，也不是检索，而是“什么东西应该放哪一层”。不分层，后面几乎一定会越做越乱。

## 1. 为什么知识系统一开始就容易变成一锅粥

很多人搭第一版个人知识库时，会把这些东西一股脑混在一起：

- 原始笔记
- AI 总结
- 检索索引
- 历史对话
- 用户偏好
- 临时任务状态

短期看，这样很省事。

但系统一旦开始长期使用，就会出现几个问题：

- 原始资料和 AI 派生内容混在一起，来源越来越不清
- 检索结果里什么都能搜到，但不知道该信哪一层
- 记忆和知识库混成一个黑箱，写进去容易，清理出来很难
- 一次临时回答留下的中间状态，反过来污染长期知识

所以个人知识系统真正需要的，不是“都存起来”，而是：

> 让不同类型的信息住在不同的层里，各自承担不同责任。

## 2. 分层不是为了复杂，而是为了分责

一个实用的个人知识系统，通常至少可以拆成四层：

| 层 | 主要保存什么 | 默认写入者 | 它主要解决什么 |
| --- | --- | --- | --- |
| Raw | 原始笔记、代码、文档、网页摘录 | 用户或原始系统 | 保留第一手资料和证据 |
| Index | 全文索引、向量索引、Metadata | 程序 | 让系统能更快找到东西 |
| Wiki | 概念、实体、项目、决定、综合页 | Agent 辅助维护 | 让零散资料变成可复用知识 |
| Memory | 偏好、任务状态、历史选择 | Agent 按规则写入 | 让系统有跨调用延续性 |

这个分层有一个很重要的好处：

- Raw 负责“真相在这里”
- Index 负责“先帮我找出来”
- Wiki 负责“把它讲清楚、连起来”
- Memory 负责“把需要延续的状态留下来”

只要四层不混，后面不管是检索、同步还是接 Agent，边界都会清楚很多。

## 3. Raw：原始资料层，负责保留证据

Raw 层就是原始资料层。

在你的场景里，它通常包括：

- Obsidian 里的原始笔记
- 本地 Markdown、PDF、截图、方案文档
- 项目代码仓库
- 网页存档或引用材料

这一层最关键的原则不是“整齐”，而是“保真”。

也就是说：

- 原始上下文尽量保留
- 不要为了统一结构强行重写原文
- 重要结论始终能回到 Raw

所以 Raw 更像第一手资料库，而不是展示层。

它回答的问题是：

> 如果我不信上层总结，我最终能回到哪里核验？

## 4. Index：索引层，负责让系统能找到材料

Raw 层有了之后，系统还不能直接高效使用。

因为“资料存在”不等于“资料可被快速定位”。

所以第二层通常是 Index，也就是索引层。

这一层常见内容包括：

- 文件路径和标题索引
- 全文倒排索引
- 向量索引
- 标签、时间、作者、项目名等 Metadata

要注意，Index 不是事实源，也不是知识结论。

它更像一张地图或目录系统，主要回答的是：

- 这个内容在哪
- 哪些片段和当前问题最相关
- 哪些文件可能值得进一步读取

所以 Index 可以重建、可以失效后重算、可以替换实现，但它不应该被当成最终知识本身。

## 5. Wiki：派生知识层，负责把零散资料组织成可复用知识

如果只有 Raw 和 Index，你已经能“找到资料”，但还不等于“理解系统”。

这时候就需要第三层：Wiki。

Wiki 层不是原文复制，而是有来源的派生知识。

它适合沉淀这些东西：

- 概念：某个方法、理论、技术点
- 实体：人物、组织、工具、产品
- 项目：目标、状态、里程碑、问题
- 决定：为什么选这个方案、当时依据是什么
- 综合：跨多篇笔记形成的模式、时间线、对照

它的价值在于：

- 把同一主题的资料聚拢起来
- 把零散记录变成更稳定的入口
- 让未来的你和 Agent 都更容易理解全貌

所以 Wiki 更像“可追溯的知识组织层”。

## 6. Memory：持续状态层，负责让系统有延续性

最后一层是 Memory。

Memory 最容易被误解成“大一点的知识库”，但它的重点其实不是资料存量，而是持续状态。

这一层更适合保存：

- 用户偏好
- 常用表达风格
- 某类任务的已知约束
- 尚未完成的任务状态
- 被验证过、值得沿用的历史选择

它不适合做的事情包括：

- 把所有聊天记录长期保留
- 把每次中间推理都记下来
- 把原始事实和临时猜测混着存

所以 Memory 的关键词是：

- 有门控
- 有生命周期
- 有作用域

不然系统就会慢慢长成一个谁也说不清的垃圾抽屉。

## 7. 四层之间到底怎么流动

把四层放在一起看，大致可以这样理解：

- Raw 是底座
- Index 帮你找
- Wiki 帮你理解
- Memory 帮你延续

最终被模型真正看到的，依然只是 Context。

这也是为什么 Part 02 讲的 Context、Knowledge Base、Memory，到 Part 03 会自然落到分层设计上。

## 8. 最容易犯的三个分层错误

### 8.1 把 AI 总结写回 Raw，当成原文

这样做的最大问题是，派生内容会反过来污染第一手资料。

更稳的方式是：

- 原文留在 Raw
- 总结写到 Wiki
- 两者之间保留来源链接

### 8.2 把 Index 当成知识层

向量库、倒排索引、metadata 系统很重要，但它们只是检索设施。

它们可以告诉你“哪里可能相关”，但不能天然替代“这一页到底在讲什么”。

### 8.3 把 Memory 当成万能缓存

如果什么都往 Memory 里丢，短期会觉得方便，长期一定会失控。

Memory 应该保存必须跨任务延续的内容，而不是替代 Wiki 或 Raw。

## 9. 这篇先记住五个结论

1. 个人知识系统至少要区分 Raw、Index、Wiki、Memory 四层。
2. Raw 负责保留原始证据，Index 负责帮助检索，Wiki 负责组织知识，Memory 负责延续状态。
3. Index 不是知识本身，Memory 也不是大号资料库。
4. 不分层，后面最容易出现来源不清、状态污染和长期失控。
5. 分层不是为了复杂，而是为了让每一层各负其责。
