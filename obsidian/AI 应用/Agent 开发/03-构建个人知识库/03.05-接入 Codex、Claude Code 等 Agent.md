# 接入 Codex、Claude Code 等 Agent

![[assets/03-05-agent-access-illustrations/01-agent-access-hero.excalidraw]]

> [!note]
> 到这里，知识库已经不只是“有很多资料”，而是开始有分层、有 Wiki、有同步机制。接下来最关键的一步，是让 Codex、Claude Code 这类 Agent 真正知道：应该先读什么、怎么读、什么时候回原文核验。

## 1. 为什么“把目录开放给 Agent”还不够

很多人接 Agent 的第一反应是：

> 我把整个仓库给它读权限，它不就能自己看了吗？

这当然是必要前提，但远远不够。

因为 Agent 即使能读文件，也不天然知道：

- 哪些文件是系统入口
- 哪些内容是原始资料，哪些是派生知识
- 回答问题时应该先查 Wiki 还是先翻原文
- 哪些目录能读，哪些目录不该碰

如果这些边界不明确，结果通常是：

- 该先看入口时它从随机笔记开始翻
- 该先看 Wiki 时它直接淹没在 Raw 里
- 该回原文核验时它只拿着一段总结硬答

所以真正的接入重点不是“给权限”，而是“给使用规则”。

## 2. Agent 最需要的不是更多资料，而是更好的入口

对人来说，知道系统结构可以靠经验。

但对 Agent 来说，最好有明确入口页告诉它：

- 这个知识系统的目标是什么
- 原始资料在哪
- Wiki 在哪
- 应该先读哪些页建立上下文
- 什么情况下应该回原始笔记核验

这也是为什么像 `purpose.md`、`schema.md`、`wiki/index.md`、`wiki/overview.md` 这种入口文件非常重要。

它们本质上是在回答：

> 如果你是第一次进这个库，先怎样理解它，才不会乱读乱写？

## 3. 一个比较稳的 Agent 读取顺序

当用户问一个基于个人资料的问题时，一个更稳的读取顺序通常是：

1. 先读入口页，理解系统边界
2. 先查 Wiki 的索引页和相关主题页
3. 如果需要证据，再沿来源回原始笔记
4. 如果还不够，再做更细的文件搜索或全文检索

这个顺序背后的逻辑很简单：

- 先建立结构，再读细节
- 先看派生知识，再回原始证据
- 先减少搜索范围，再进入大海捞针

也就是说，Wiki 在这里不只是知识层，还是 Agent 的导航层。

## 4. 为什么“先查 Wiki，再回原文”通常比“直接搜全库”更好

直接搜全库当然也能工作，但它有几个常见问题：

- 召回很多噪音
- 重复读大量相似笔记
- 把草稿和结论混在一起看
- 不知道哪段内容在全局里更重要

而“先查 Wiki，再回原文”能带来几个好处：

- 更容易先抓到全局主题
- 更容易知道该回哪几个来源核验
- 更容易让回答带结构，而不是碎片拼接

所以 Wiki 在 Agent 接入里扮演的，不只是摘要层，更像一个问题路由层。

## 5. 精确搜索和语义检索，应该怎样配合

Agent 进入知识库后，通常不会只靠一种搜索方式。

更实用的组合往往是：

- 精确搜索：文件名、标题、关键词、标签、路径
- 全文搜索：定位明确提法和具体表述
- 语义检索：找“意思相关但表述不一样”的内容

大致可以这样分工：

| 方式 | 更适合做什么 |
| --- | --- |
| 路径/标题搜索 | 快速定位已知主题或已知页面 |
| 全文搜索 | 找关键句、引用、原始描述 |
| 语义检索 | 找相关经验、隐含相似问题 |

真正稳的 Agent，不是只会一种搜法，而是知道什么时候该换档。

## 6. 什么情况下必须回原文核验

不是所有问题都只靠 Wiki 就能回答。

以下几类情况，最好强制回原始来源核验：

- 用户要精确事实、原话、原时间线
- Wiki 页面本身标了“待核实”
- 多个来源之间存在冲突
- 回答会影响重要决策或外部输出

换句话说：

> Wiki 可以帮助 Agent 更快理解问题，但 Raw 仍然是最终证据层。

## 7. 让 Agent 真正用好知识库，通常还需要哪些规则

除了入口和读取顺序之外，最好再给 Agent 一些显式规则，比如：

- 未经明确要求，不修改原始资料
- 优先引用 Wiki 页面，但在关键处标明原始来源
- 证据不足时写明“不确定”或“待核实”
- 发现系统结构问题时，先报告，再决定是否写回

这些规则看起来很朴素，但它们决定了 Agent 是在“帮你用知识库”，还是在“随机翻动你的资料”。

## 8. 接 Agent 的本质，是把知识系统变成一个可被消费的接口

讲到这里你会发现，所谓“让 Agent 接个人知识库”，本质上不是给它更多内容，而是把这套系统变成一个清晰接口。

这个接口至少要回答：

- 先看哪里
- 再看哪里
- 哪些层能直接信，哪些层要回查
- 哪些内容允许读，哪些内容不允许动

一旦这些规则清楚，Agent 才会从“会搜文件”进化成“会使用个人知识系统”。

## 9. 这篇先记住五个结论

1. 把目录开放给 Agent 还不够，真正关键的是明确入口、边界和读取顺序。
2. Agent 最需要的不是更多资料，而是更好的导航入口。
3. 一个稳妥的顺序通常是：先读入口，先查 Wiki，再回原文核验，必要时再扩大搜索。
4. Wiki 既是知识层，也是 Agent 的问题路由层。
5. Raw 仍然是最终证据层，关键问题不能只靠摘要硬答。
